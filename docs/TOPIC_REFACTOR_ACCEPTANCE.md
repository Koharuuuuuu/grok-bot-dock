- 以主题组织内容，提供关注、有更新、全部主题、已归档；未分组是筛选条件，没有额外的待整理收件箱。置顶只出现在关注页。

## 升级与回退

新增 REST 契约沿用现有会话或 Bearer 鉴权：`GET /api/v1/topics`；`PATCH /api/v1/topics/{id}`（名称、分组、关注、置顶及生命周期动作）；`GET /api/v1/topics/{id}/reports`（支持 `q`、`cursor`、`limit`）；`POST /api/v1/topics/{id}/read`（`report_id: 0` 表示全部）；`POST /api/v1/topics/sync`。发布增加可选 `topic_id`、`topic_name`，响应返回稳定主题 ID。全局搜索增加 `topic_tab`、`topic_group`，原调用方式继续有效。

MCP 新增 `sync_topic_state`，使用 `reports:write` scope；发布与同步必须复用同一 `source` 和 `bot_id` 或 `stable_task_id`。停止确认使用同步响应中的 `revision`，手工证据确认也绑定当前版本；过期确认被拒绝。

OAuth 客户端管理中的“请求删除并通知”会针对所选客户端创建带版本的断开请求。此后该客户端的 OAuth Token 只能调用 `sync_connection_state`，其他 MCP 工具立即被拒绝。客户端收到断开指令、移除自己的本地连接后，必须用同一版本确认；服务端随后原子清除客户端注册、授权码、授权和 Token。服务端 SSE 会让打开着的所有者管理页及时刷新。客户端离线时，请求保持等待；所有者可选择“强制删除”，这会立即清除本端记录并明确提示需手动清理离线客户端。

MCP 不提供服务端向离线客户端推送的通道。因此“通知对接方”是有鉴权的下次检查握手，不会伪称网络推送。握手状态存储在 v6 的 `oauth_client_disconnects` 表，OAuth 客户端通过现有 API 得到版本和时间；Token 过期后允许重新走 OAuth 授权以恢复握手，但待删除 Token 仍只能调用断开工具。已存在的数据库升级时自动创建该表，不更动旧客户端和授权。SSE 事件用 `acknowledged` 与 `forced` 区分客户端确认和所有者强制删除，管理页使用独立刷新计时器，不会取消主题数据刷新。

启动时自动执行原子 v5 迁移，将每个旧任务映射到确定性的主题，保留报告、用户显示名称及已有阅读水位。新增主题、任务关联和逐篇阅读记录，不删除旧业务数据。迁移重启安全已经测试。

正式升级前先停止服务并备份完整数据目录；若不停服，应使用 SQLite 一致性备份，而不是只复制正在写入的主数据库。回退时停止服务，恢复升级前的完整数据库备份和旧程序。不要让旧程序继续写入 v5 数据库：旧程序不理解新增的主题关联语义。

## 验收边界

本次证明的是仓库内代码、真实 HTTP/MCP/SQLite 与本地浏览器构成的闭环，不等于证明所有环境永远无缺陷。没有部署生产，也没有操作真实 Grok 任务或第三方账户。贡献任务停止确认使用本地测试客户端模拟，不能据此声称外部任务已经关闭。

真实平台能否自动接入、能否取消定时任务，取决于其远程 MCP 和调度权限；客户端不支持时文案必须如实提示。归组、关注和未分组不会触发模型调用；外部任务应在耗费 Token 前同步停止状态，未实施该协议的外部调度仍需在对应平台手动停止。
