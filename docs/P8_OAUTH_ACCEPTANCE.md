## OAuth 2.1 scope statement

**This is not a claim of complete OAuth 2.1 implementation or full MCP Authorization specification conformance.** As of 2026-10-10, the IETF Datatracker lists `draft-ietf-oauth-v2-1-16` as an Active Internet-Draft with no intended RFC status set ([current Datatracker record](https://datatracker.ietf.org/doc/draft-ietf-oauth-v2-1/)). The current MCP authorization baseline is the `2026-07-28` specification ([authorization spec](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)). Bolt Dock implements a scoped Authorization Code + PKCE S256 profile with MCP discovery/resource binding, CIMD retrieval and consent. Local compatibility fixes cover omitted `redirect_uri` where OAuth 2.1 permits it, unique-parameter enforcement, and rejection of mixed client-authentication methods. Independent conformance and real-client interoperability remain unverified; refresh tokens and DCR remain outside the implementation. For P7 compatibility, `/mcp` continues to accept the shared legacy `ACCESS_TOKEN` alongside OAuth access tokens. The MCP authorization profile requires tokens issued specifically for this protected resource, so accepting this non-OAuth shared credential is an intentional compatibility exception and prevents a full-profile-conformance claim. Describe the service as implementing a limited OAuth profile, not “fully OAuth 2.1 compliant.”
