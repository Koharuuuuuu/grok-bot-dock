# P9.1 · PC 顶栏响应式回归修复（Codex 严格执行计划）

> 状态：**待修复 / 待验收**。2026-10-12 用户报告：P9 移动端适配后，PC 宽屏顶部右侧统计与操作区严重压缩，呈纵向堆叠。用户截图为问题证据（浏览器访问 `grok.nyaco.cn`，深色主题，约 1839px 截图宽度）；截图已在对话中提供，Codex 如无法直接读取对话附件，应以真实页面或本地复现为准，**不可声称已获得该图片文件**。本任务优先级高于新功能迭代。
>
> 目标：**只修复 PC 顶栏布局回归，保留已修好的手机端和现有视觉风格**；不是重新设计 UI，也不改变分享、报告、MCP/OAuth 业务。

## 1. 问题描述与期望

截图可见：Logo 和左侧搜索框基本正常，下方报告卡片仍能以多列排列；**顶部右侧**的“全部来源 · 0 未读”、主题按钮、`10 BOTS`、`27 报告`、`5.4 MB 全库`、实时同步状态/图标被挤进窄条，数字、标签与按钮纵向叠在一起，出现异常高度和换行。说明问题集中在顶栏右侧宽度分配或响应式样式，不能仅凭截图断定唯一 CSS 根因。

桌面端应在可用宽度内保持清晰的水平布局：品牌、搜索、来源选择、主题、统计数据与实时同步互不覆盖；数字和标签有可读的排版。**不要求强制所有元素挤在同一行**：中等宽度允许有序分区或折行，但不得形成窄列、重叠、裁切或横向滚动。

## 2. Codex 执行顺序（逐项打勾）

### Phase A · 审计与复现

- [ ] 从最新 `master` 开始，记录基线 SHA、P9 最近响应式相关提交；检查真实顶栏组件及 CSS（含全局 CSS、媒体查询、容器查询、`flex/grid`、`min-width`、`max-width`、`flex-shrink`、`flex-basis`、`grid-template-columns`、`white-space`、`overflow`）。
- [ ] 在桌面宽度 1024、1280、1366、1440、1600、1920px 复现；重点关注浏览器截图约 1839px 宽、深色主题、来源筛选非空、统计文本和同步指示器。
- [ ] 使用浏览器开发者工具/自动化浏览器检查右侧父容器与子节点的 `getBoundingClientRect()`、计算样式和换行情况；查清究竟是父容器收缩、断点命中、栅格分配还是子项不合理换行，记录证据。
- [ ] 对比移动端修复前后差异，确认造成 PC 回归的具体规则；**禁止仅添加任意 `!important`、全局固定宽度或依靠 `overflow:hidden` 掩盖问题**。

### Phase B · 最小范围修复

- [ ] 优先修改顶栏相关组件和局部 CSS，避免触碰卡片栅格、报告详情、分享页、MCP/OAuth 与业务 API。
- [ ] 宽屏使用明确的布局分区：左侧品牌、中央可伸缩搜索、右侧来源/主题/统计/同步。为右侧设置合理的内容宽度约束和必要的 `flex-shrink:0` / `min-width:max-content`（按实际布局选用）；搜索区可收缩且需 `min-width:0`，避免占满右侧空间。
- [ ] 统计项在 PC 端横向排布，数值与标签成组且可读，实时同步指示器与文字不应被挤成竖列；来源下拉可显示选中值并允许长名称省略，展开后内容可见。
- [ ] 不盲目强制 `white-space:nowrap` 于整个顶栏：只保护必要的数字、图标和短标签；较窄桌面按合理断点分组、折行或收纳，避免溢出。
- [ ] 断点规则必须互斥或优先级清晰：手机 ≤767px、平板 768–1023px、PC ≥1024px 为**测试分组而非未经审计就强加的 CSS 断点**。不得让手机端 `flex-direction:column`、全宽按钮、`grid-template-columns:1fr` 等规则污染 PC。
- [ ] 保持手机端已修复的主题切换、信源选择、select 文本、点击热区、抽屉/弹层与安全区行为，保留主题偏好和筛选逻辑。

## 3. 强制验收条件

1. PC ≥1024px 右侧统计信息恢复正常排版，来源/主题/同步不再被压成竖条；至少覆盖 1280、1440、1920px。
2. 320–430px 手机端的主题切换、信源 select 和顶部操作区继续可读、可操作，无重叠。
3. 768–1023px 过渡自然；长名称、放大缩放、深浅主题无异常。
4. 自动化几何断言 + 实际浏览器截图 + 构建/回归测试均有证据。
5. 不引入新的后端接口、数据库迁移、权限变更、数据清理或生产部署。
