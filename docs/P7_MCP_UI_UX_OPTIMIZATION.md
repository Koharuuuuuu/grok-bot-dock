# P7 · MCP 通用接入界面 UI/UX 优化与执行清单

> 2026-10-10 用户确认。**本文件是交给 Codex 的待执行任务，不代表功能已实现。** 目标分支 master。与 [P7 MCP 独立服务定位纠偏](./P7_MCP_PRODUCT_POSITIONING_CORRECTION.md) 配套执行。Bot Dock 是独立 MCP Server；Codex 是开发工具，不是产品必需组件。任何兼容自定义远程 MCP 的 Agent 都可在授权后调用，具体第三方平台是否支持必须实测。

## 一、产品信息架构与文案

- [ ] 在现有 Web 工作台的合理位置设置中立入口 **「MCP 接入」**（可在现有「推送指令」入口附近或集成页中呈现），不以 Codex 命名入口、页面标题、主操作按钮。
- [ ] 页面主标题「MCP 服务接入」，副标题「将 Bot Dock 作为 MCP 服务，供支持远程 MCP 的 AI Agent 发布和查询报告」；不得承诺“所有 AI 均可直接连接”。
- [ ] 清晰区分两个路径：**MCP（支持 MCP 的 Agent）** 与 **REST API（脚本、Webhook 或不支持 MCP 的平台）**。现有 REST 推送指令保留、可发现，不强迫用户切换。
- [ ] 不出现“启动 Codex”“必须安装 Codex”“Codex MCP 配置已复制”等默认指引。Codex、Claude 等仅可出现在可选「客户端配置示例」中，且不应抢占主视图。

## 二、推荐页面结构（按现有视觉系统落地，不推倒重做）

### 区块 A：服务连接信息（首屏最重要）
- [ ] 展示「MCP 服务地址」：由当前站点可用外部 origin + `/mcp` 推导，支持复制；**反向代理场景**允许用户显式覆盖公开地址并本地保存，不得生成 localhost 或内网地址冒充公网可用。
- [ ] 展示「传输协议：Streamable HTTP」「鉴权方式：Bearer Token」及状态标签；状态仅基于真实探测/服务器能力得出，不能仅因页面打开就标“在线”。
- [ ] 「复制服务地址」按钮复制纯 URL，反馈“已复制 MCP 服务地址”；「复制通用接入说明」复制协议、URL、鉴权头格式和工具清单，不包含密钥。
- [ ] 提供一键复制无密钥的通用配置示例（如 JSON/说明文本），不得把 Codex 专属配置伪装成标准 MCP 通用 JSON；协议不定义统一的客户端配置文件格式。

### 区块 B：认证与 Token 安全
- [ ] 说明当前 P7 若复用服务器 `ACCESS_TOKEN`，这属于**单用户受信任接入**，不是独立生成的 MCP Token；界面不可假装存在 Token 发行/撤销能力。
- [ ] 不回显服务器环境变量 `ACCESS_TOKEN`，不将 Token 写入剪贴板模板、localStorage、URL、日志、示例配置或截图；仅提示用户在目标客户端的安全凭据设置中填写。
- [ ] 将 `BOLT_DOCK_TOKEN` 解释为**部分客户端示例自选的本地环境变量名**，并非 MCP 标准要求，也非服务器端必须设置的变量；仅当展开相关示例时出现。
- [ ] 如后续实现独立 Agent Token 管理，需另立安全设计/迁移计划：按 Agent 发行、权限（只写/只读/读写）、撤销、过期、哈希存储、仅显示一次。**不得在本次纯 UI 改动中制造假的 Token 管理入口。**

### 区块 C：工具能力
- [ ] 显示实际已注册且可调用的工具，至少 `publish_report`（提交 Markdown 报告）与 `search_reports`（检索历史报告）；从后端能力或共享定义获取，避免展示未实现工具。
- [ ] 对每个工具给出用途、主要字段、读/写性质和简短调用示例（示例不得包含凭据）。`publish_report` 强调 `executed_at`、`content`、稳定 Bot 身份、可选 `external_id` 幂等；`search_reports` 强调 query 与分页限制。
- [ ] 清楚区分“Agent 可以发现并调用工具”与“Agent 必然自动推送”。自动调用取决于目标 AI 客户端的能力、权限与提示/任务配置。

### 区块 D：接入步骤与可选客户端示例
- [ ] 用三步说明：① 复制 MCP URL ② 在支持自定义远程 MCP 的客户端中配置 URL 和 Bearer 凭据 ③ 允许调用 `publish_report` 并在 Bot Dock 查看结果。
- [ ] 客户端示例（Codex / Claude / Grok 等）采用折叠/次级信息层；只有核实对应**具体产品形态及版本**支持自定义远程 MCP 后才能标注“已验证”，否则显示“需确认支持情况”。特别不能断言所有 Grok Bot 都支持自定义 MCP。
- [ ] 失败排查：401（Token 错误）、404（代理未转发 /mcp）、协议不兼容、客户端不支持远程 MCP、Origin/HTTPS 限制；不泄露敏感信息。

## 三、视觉与交互约束
- [ ] 沿用现有 Bot Dock 的视觉语言、组件、间距、配色、深浅主题、字体及浮层行为；不大规模重构首页。
- [ ] 桌面端信息分组明确，移动端 320/375/390/430px 无横向溢出；长 URL 可截断显示但复制必须完整；按钮不重叠，点击区域可用。
- [ ] 模态/抽屉打开关闭无页面抖动，支持 Esc、焦点管理、键盘访问、关闭后焦点返回；不破坏 P6 已修复的详情弹窗和阅读体验。
- [ ] 复制成功/失败反馈与**实际复制内容**一致；不使用误导性的“已配置成功”来描述仅复制了文本。
- [ ] 所有标签与提示统一简体中文；错误信息清晰，空状态与加载状态有反馈。

## 四、开发与测试要求
- [ ] 先定位当前 MCP 入口、按钮文案、复制逻辑、客户端模板和前端组件，记录现状截图/问题清单；优先最小改动。
- [ ] 如服务端尚未真正实现某个 MCP 工具，界面不得提前显示“已就绪”；状态及工具清单应与实际部署能力一致。
- [ ] 单元测试覆盖 URL 推导/覆盖、复制文本、不含 Token、默认无 Codex 专属文案、条件展示工具；集成测试覆盖 /mcp 实际可用性和认证。
- [ ] 真实浏览器验收：桌面 1440/1280、移动 320/375/390/430、深浅主题；复制 URL 和说明后实际粘贴核对；登录/刷新/退出、弹窗开合、旧 REST 推送功能回归。
- [ ] 在 `docs/P7_MCP_ACCEPTANCE.md` 增加「通用 MCP UI/UX」验收小节：修改前后截图路径、测试命令、结果、未验证客户端及部署限制；**未测不勾选**。

## 五、Codex 交付边界

1. 本 UI 任务与 P7 MCP 后端任务协同；优先实现**通用服务入口**，不要求用户先安装任何特定 AI 客户端。
2. 保留 `/mcp`、REST API、数据库结构、GHCR 镜像名、Docker 单容器、`/data` 以及已完成 P6 功能。
3. 通过仓库规定的 PR/CI 流程合并 master；若需真实外部平台账号才能验证，记录阻塞，不得编造测试结果。
4. 最终 UI 必须让首次使用者看懂：**「这是我的 MCP 服务地址；任何支持该协议并获得授权的 AI 客户端都可以连接并推送报告」**。
